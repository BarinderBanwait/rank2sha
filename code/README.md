# `code` — the computations of Part 2

Every number quoted in Part 2 of *Second derivatives of $p$-adic $L$-functions
and the Shafarevich–Tate group of rank-two CM elliptic curves* is produced by a
script in this directory and recorded in a file under `data/`. This README maps
each number to both.

Part 2 treats the five rank-two curves $y^2 = x^3 - Dx$ of Coates, Liang and
Sujatha, $D = 56, 17, -33, -34, -39$. Every one has CM by $\mathbb{Z}[i]$, rank
two, root number $+1$, torsion $\mathbb{Z}/2$ generated by $(0,0)$, analytic
order of Sha equal to 1, and isogeny degrees $[1,2]$.

| $D$ | LMFDB | $N$ | $\mathfrak{f}$ | $\mathrm{Nm}(\mathfrak{f})$ | $\#\mathrm{Cl}_\mathfrak{f}(K)$ | $\prod_v c_v$ | MW basis |
|---|---|---|---|---|---|---|---|
| 56 | `12544.g1` | 12544 | $(56)$ | 3136 | 384 | 4 | $(8,8)$, $(9,15)$ |
| 17 | `9248.c1` | 9248 | $(1+i)^3(17)$ | 2312 | 256 | 4 | $(-1,4)$, $(-4,-2)$ |
| $-33$ | `69696.i2` | 69696 | $(132)$ | 17424 | 1920 | 4 | $(4,14)$, $(16,68)$ |
| $-34$ | `73984.d2` | 73984 | $(136)$ | 18496 | 2048 | 4 | $(8,28)$, $(32,184)$ |
| $-39$ | `48672.n2` | 48672 | $(1+i)^3(39)$ | 12168 | 1152 | 8 | $(3,12)$, $(27,144)$ |

The curve $D = 56$ is the testbed of Part 1, 2-isogenous to the curve
$y^2 = x^3 + 14x$ of CLS. The LMFDB rows are in `data/lmfdb_five_curves.json`
(pulled 2026-09-05) and are quoted, not recomputed; see §1.8 of the paper. The
Mordell–Weil bases of the four curves other than $D = 56$ are in
`data/family_bases.txt`, saturated at every prime up to 30011.

## Requirements

| Software | Version used | What needs it |
|---|---|---|
| PARI/GP | 2.17.2 | everything under `gp/` |
| SageMath | 10.7 | the SageMath scripts under `sage/` |
| Python 3 | 3.13 | the plain-Python checks under `sage/` |

Run

```bash
./build.sh
```

from this directory. It reports what it finds, prints the exact install command
for anything missing, checks that every data file the scripts read is present,
and runs a smoke test. It installs nothing on its own.

To install by hand:

```bash
brew install pari          # macOS
sudo apt install pari-gp   # Debian/Ubuntu
```

SageMath is a larger dependency. It is needed by `sage/certificates.sage` and
`sage/regulator.sage`, the two halves of the control that `sage/run.sh` drives,
by `sage/m2_msd.sage` and `sage/m2_msd_family.sage` for $\kappa(p)$, by
`sage/unit_ms_family.py` for the unit condition below 1000, and by
`sage/family_crosscheck.py` and `sage/e4_577.py` for the CLS family; everything
under `gp/` and every plain-Python script under `sage/` runs without it. Install instructions are at
<https://doc.sagemath.org/html/en/installation/>.

## Layout

```
gp/      PARI/GP scripts
sage/    SageMath and plain-Python scripts
data/    the output of every run
legacy/  retired computations; gitignored, not published, supports nothing
```

Section numbers below are those of the manuscript as it stands. They move as the
paper is edited; the LaTeX labels each script names in its header (`ssec:scan`,
`prop:scaneq`, `eq:Sexc`, and so on) do not, and are the reference to trust if
the two ever disagree.

Each script resolves its data paths as `../data/`, so **run it from the directory
it sits in**. Each prints a header saying what it computes and which part of the
paper it backs, writes its result to `data/`, and ends with a terminal `DONE`
marker, so a clean run leaves evidence of being clean.

## Running the computations

### The horizontal regulator scan (§5.3)

The interval is given by the environment. The paper scans every split prime
below 30,000, which is the range in which `prop:scaneq` makes a clean prime a
verification:

```bash
cd gp
LO=5 HI=29999 OUT=../data/all_primes_vreg.txt gp -q scan.gp
```

(the script refuses to start if the output file exists, so move the committed one
aside first). That is 1611 split primes, and it reproduces
`data/all_primes_vreg.txt` byte for byte. Per-prime cost runs from 5 ms at
$p = 101$ to 4.9 s at $p = 29989$, so the single interval is over an hour;
splitting it into seven chunks run in parallel brought the last 1103 primes in
under **13 minutes** on an eight-core Apple M1 Pro. Chunks concatenated in
increasing order of $p$ give the committed file.

A re-run writes a terminal `JOBDONE` line that the committed file does not carry,
so compare on the data lines.

The working precision follows the rule stated in §5.3: $n = 6$ below 2000,
$n = 5$ below $10^4$, $n = 4$ above. If a computed valuation $v$ satisfies
$v \ge n-1$, where finite precision could mask a larger true valuation, the prime
is recomputed at precision $n+4$ and its line flagged `ESC`. No line in the
committed output carries a flag.

### The CLS-family scan

The same quantity is computed for the four other rank-two curves of Coates, Liang and Sujatha, $y^2 = x^3 - Dx$ with $D = 17, -33, -34, -39$, at every split prime of good reduction below 30,000. Run one curve with
```bash
cd gp
D=-39 G="[[3,12],[27,144]]" LO=5 HI=29999 OUT=../data/scan_D-39.txt gp -q scan_family.gp
```
The bases are in `data/family_bases.txt` and must be used as given, since the valuation depends on the lattice. Set `RESUME=1` to continue an interrupted run from its last recorded prime.

The one case below 30,000 that Coates, Liang and Sujatha left open, $p = 577$ for $y^2 = x^3 + 34x$, is decided by `sage/e4_577.py`, which computes the $577$-adic $L$-function from eclib modular symbols in about a minute and records the invariants that place $577$ outside $S_E$. Its second coefficient is $529 + O(577)$, a unit.

### The control on the normalisation (§5.3)

```bash
cd sage && ./run.sh 5 8 5 3600                  # D = 56, output data/cert_5.out
cd sage && D=-39 EXPECT_V=1 ./run.sh 5 9 5 3600 # output data/cert_D-39_p5.out
```

This runs the two independent implementations of $\operatorname{Reg}_\mathfrak{p}$
(PARI's `ellpadicregulator` and Sage's `padic_regulator`), the modular-symbol
$L$-side with the Stein–Wuthrich truncation bounds, and a mechanical cross-check
of all of it. The curve is the environment variable `D`, default 56; the
Mordell–Weil basis is read from `data/family_bases.txt`; the output is
`data/cert_<p>.out` for $D = 56$ and `data/cert_D<D>_p<p>.out` otherwise.
`EXPECT_V` is the expected $v_p(c_2(p))$ of check C6 and is 0 unless the unit
condition fails at $p$, which happens at $(D,p) = (-33,37)$ and $(-39,5)$, where
it is 1.

$p = 5$ takes about a minute. **$p = 13$ at $D = 56$ takes about 96 minutes**,
almost all of it in the modular-symbol sum, which is $(p-1)p^{n-1}$ measures —
exponential in the number of certified digits. `run.sh` never lets a
lower-precision run replace a higher-precision certificate, so it is safe to
re-run at any $n$, in any order.

### The unit condition by modular symbols below 1000

```bash
cd sage && D=-34 sage unit_ms_family.py
cd sage && python3 verify_unit_ms.py
```

For each of the five curves and every split prime $5 \le p < 1000$ of good
reduction, `unit_ms_family.py` forms $L_p(E,T)$ from eclib modular symbols at
$n = 2$ and records $v_p(c_2)$, certified modulo $p$; a prime at which that does
not separate $c_2$ from 0 is rerun at $n = 3$. About 15 minutes per curve, and
the five are independent. `verify_unit_ms.py` compares the result with the
regulator scan at every prime outside $S_E$ and with the LMFDB valuations of the
$p$-adic regulator, and exits 0 when they agree.

### The bracket $B(\mathfrak{p})$ (§6.8)

```bash
cd gp && gp -q m2_w1.gp                                  # D = 56, p = 5, 13, 17
cd gp && W1PRIMES=29,37 W1PREC=600 W1OUT=../data/m2_w1_2937.out gp -q m2_w1.gp
```

The first is about 25 seconds and reproduces `data/m2_w1.out`; the second is
about 18 minutes, the cost growing like $p^4$, and reproduces
`data/m2_w1_2937.out`. Both stage their output and move it onto `data/` only if
every gate passes, so an interrupted run leaves the committed file alone and its
partial output in `.partial`.

`gp/m2_w1_family.gp` does the same for any of the five curves:

```bash
cd gp && D=-39 W1PRIMES=29,17,5 W1PREC=600 gp -q m2_w1_family.gp
cd gp && D=17 W1PRIMES=37,29,13 W1PREC=600 gp -q m2_w1_family.gp
```

The cost is $\#\mathrm{Cl}_\mathfrak{f}(K)$ times a per-class cost that grows
like $p^4$ and does not depend on the conductor, so it runs from 14 seconds at
$(D,p) = (-39,5)$ to 19 minutes at $(-34,29)$. The class sums are recognised in
$K = \mathbb{Q}(i)$; the run gates the conductor, the class count against
`bnrinit`, the character $\varepsilon$ and its closed form, the quasi-period
identity that fixes the period-lattice generator, the fast slot routines against
a full bivariate expansion, and, for $D = 56$, the fourteen class sums of
`gp/m2_w1.gp`.

The modular-symbol side the bracket is checked against is

```bash
cd sage && sage m2_msd.sage                              # D = 56
cd sage && D=-33 PRIMES=37,17,13 sage m2_msd_family.sage
```

about three minutes and about fifteen seconds respectively. `m2_msd.sage`
reproduces `data/m2_msd.out`, whose $\kappa(p)$ table is transcribed into
`gp/m2_w1.gp`; `m2_msd_family.sage` writes `KAPPA p v` lines that
`gp/m2_w1_family.gp` reads at run time from `data/m2_msd_D<D>.out`, and prints
the kappa gate as SKIPPED if the file is absent.

## Reading the output files

- `all_primes_vreg.txt` — one line per split prime, `p v`, with ` ESC` and
  ` MAXED` appended if the escalation rule fired. 1611 lines: every prime
  $p \equiv 1 \bmod 4$ with $5 \le p \le 29989$, in increasing order, and no
  other. No line carries a flag and every $v$ is 2.
- The four files `data/scan_D*.txt` have the format of `all_primes_vreg.txt`, one line `p v` per split prime of good reduction with the same flags; the split primes dividing $D$ are absent, so $D = 17, -34, -39$ have 1610 lines and $D = -33$ has 1611. The lines with $v \ne 2$ are $p = 5$ for $D = 17$ and $D = -33$ (anomalous, excluded from $S_E$), $p = 37$ for $D = -33$, and $p = 5$ and $p = 15289$ for $D = -39$.
- `cert_5.out`, `cert_13.out` — the full transcript of a control run, header
  first, then the four stages, then the verdict. `MACHINE` lines carry the
  $p$-adic expansions in a fixed format so that the cross-checks compare digits
  mechanically rather than by eye. On `cert_13.out` see the note below.
- `m2_w1.out`, `m2_w1_2937.out` — one block per prime: the three class sums with
  their exactness residuals, the Euler factors, the three term valuations,
  $v_p(B_{\mathrm{alg}})$ and $p^{-2}B_{\mathrm{alg}} \bmod p$, and the comparison
  against $\kappa(p)$. The file ends with a gate tally: 11 of 11 and 8 of 8.
- `m2_msd.out` — $\kappa(p)$ in the Mazur–Tate–Teitelbaum normalisation at
  fourteen split primes.
- `epsilon_family.out` — one block per curve: the conductor in closed form, the
  number of ideals of $\mathbb{Z}[i]$ of that norm, $w(E)$, $a_5$, the counts of
  the three checks on $\varepsilon$, $\#\mathrm{Cl}_\mathfrak{f}(K)$ with its
  structure, and the index of the LMFDB generators in the saturated basis. Ends
  with a tally, 34 of 34.
- `excluded_set_family.out` — one block per curve, the five sets of `eq:Sexc`
  with the quantity each is the support of, then $S_E$, the split primes in it,
  and those of good reduction. A summary table repeats the last three columns.
- `cert_D<D>_p<p>.out` — the control at the four curves other than $D = 56$, in
  the format of `cert_5.out`.
- `unit_ms_D<D>.txt` — one line per split prime below 1000, `p a_p n v_p(c2)
  c2 mod p prec(c2) c0 c1 seconds`, then the counts and the exceptions. `n` is 2
  except where $c_2$ had to be certified modulo $p^2$.
- `m2_w1_D<D>.out` — the format of `m2_w1.out`, with the
  class sums written as elements of $\mathbb{Q}(i)$ and with the extra gates on
  the conductor, the class count, $\varepsilon$, the quasi-period identity and
  the bivariate expansion.
- `m2_msd_D<D>.out` — the format of `m2_msd.out`, ending with the `KAPPA p v`
  lines that `gp/m2_w1_family.gp` reads.
- `lmfdb_iwasawa.txt` — the LMFDB Iwasawa invariants of the curve, read by
  `check_agreement.py` for its last check. Corroboration only: the control does
  not depend on it, and the check reports itself skipped if the file is absent.

## Notes on the runs

These are the details behind the numbers the paper quotes. The paper states what
the computations establish; what follows is how they behave, and what was found
along the way.

### The unit character, re-determined (`gp/epsilon_check.gp`, `gp/epsilon_family.gp`)

The unit character $\varepsilon$ of $\psi_E$ was not assumed. It was read off
class by class from Deuring's relation $a_p = \psi_E(\mathfrak{p}) +
\overline{\psi_E(\mathfrak{p})}$ and found to agree with the inverse quartic
residue symbol $(56/\cdot)_4^{-1}$ at every split prime tested.

The script as shipped records the unit class the first time it is determined for
a residue class and never re-examines it, so as it stands it assigns
$\varepsilon$ rather than certifying it. The agreement was therefore checked
separately, by re-running the determination without that first-write guard and
comparing every prime against the stored class, over 3018 split primes and with
no conflict.

`gp/epsilon_family.gp` does the same for all five curves over the split primes
below $10^6$, about 39,000 per curve, and adds two checks: that
$\varepsilon(\bar g) = \overline{\varepsilon(g)}$ on the whole divisor, and that
the number of classes enumerated equals $\#\mathrm{Cl}_\mathfrak{f}(K)$ as
`bnrinit` computes it. The conductor is derived in closed form:
$\mathrm{Nm}(\mathfrak{f}) = N/4 = 2^e m^2$ with $m$ odd, and $\mathfrak{f}$ is
the conjugation-stable ideal $(1+i)^e(m)$ of that norm. The uniqueness shortcut
of `gp/excluded_set.gp` — that there is only one ideal of norm $N/4$ — holds for
$D = 56$ and $D = -33$ only; for $D = 17, -34, -39$ there are three.

### The bracket run (`gp/m2_w1.gp`)

Cost grows like $p^4$: about 2 seconds at $p = 5$ and 519 seconds at $p = 37$,
and it rises faster still once the class sums outgrow the working precision.
Five primes are reported rather than a range for that reason.

Each class sum is recognised as an element of $K$ and accepted only if the
residual is below $2^{-400}$; each came out rational, with denominator prime to
$p$, and the worst residual observed was $2^{-985}$. The Euler factors are
computed in $\mathbb{Z}_p$ to $O(p^{4p+12})$, far beyond the modulus $p^3$ at
which $v_\mathfrak{p}(B(\mathfrak{p})) = 2$ is decided. The script writes its
data file only if every gate passes: eleven of eleven at $p = 5, 13, 17$ and
eight of eight at $p = 29, 37$.

One observation from the run is worth recording, since nothing forces it. The
divisibility by $p^2$ is termwise at $p = 5, 13, 17, 37$, each of the three terms
of the bracket having valuation 2, and is not termwise at $p = 29$, where the
three valuations are 3, 2, 3.

### The bracket for the other four curves (`gp/m2_w1_family.gp`)

Three things change with the curve. The period lattice is generated over
$\mathbb{Z}[i]$ by $\Omega = \omega_1$ for $D > 0$ and by
$\Omega = \omega_1(1+i)/2$ for $D < 0$; the quasi-period identity
$\eta(\Omega) = \bar\Omega/A$ separates the two by 250 bits and is gated. The
divisor is enumerated as the primary residues coprime to $\mathfrak{f}$ in the
box of `idealhnf(K, f_0)`, which is not a square box when $e$ is odd. And the
three class sums are no longer rational: they lie in $K = \mathbb{Q}(i)$, on the
line $\overline{S} = u^{-(2p-1)}S$ where
$u = (\bar\Omega/\Omega)(\mathfrak{f}_0/\bar{\mathfrak{f}}_0)$, which is $1$ for
$D = 56$, $-1$ for $D = -39$ and $-i$ for the other three. Real and imaginary
parts are recognised separately, with denominators searched up to
$10^{\mathrm{W1PREC}/3}$ and accepted only below $10^{\mathrm{W1PREC}/6}$, so a
sum that is not a rational of that height fails the gate instead of being fitted
to numerical noise. The $p$-adic bracket is then formed through the embedding
$i \mapsto i_p$ fixed by the labelling of $\mathfrak{p}$.

The pair $(D,p) = (-33,37)$, the second exception of the scan, has no bracket
file. The run at realprecision 600, 1920 classes, took 2779 seconds and failed
the exactness gate: the third class sum $S[0,2p-2]$ came back with a
denominator at the search bound and did not satisfy the conjugation relation,
while the other two were clean, so the $(0,2p-2)$ slot loses about 240 digits
at this class count and 600 is not enough. No output was written, by design. A
run at higher precision was not made; the paper reports the pair, together
with $(-39, 15289)$, as a gap.

## A note on `cert_13.out`

`cert_13.out` was produced before the scripts were put on the paper's
Mordell–Weil basis, and records

```
MW basis          : [-7, 7], [9, 15]
```

where the paper and `cert_5.out` use $(8,8)$, $(9,15)$. The two bases generate
the same subgroup of $E(\mathbb{Q})$ modulo torsion: $(8,8) - (-7,7) = (0,0)$,
the generator of the torsion. The $p$-adic regulator is therefore the same
element, and not merely an element of the same valuation — at $p = 13$ and
working precision $n = 14$ the two lifts agree at $O(13^{16})$, in PARI/GP and in
SageMath independently. The $L$-side of the control uses no Mordell–Weil basis at
all.

No number in the file depends on the choice, so the file was not regenerated: the
modular-symbol stage costs 96 minutes and would return the same digits. Its text
also carries the section names of a superseded draft — `A5 CERTIFICATE`,
`eq:match5`, `Appendix B`. Read it as a transcript of the computation
`cert_5.out` records, at the other prime.

## What is not here

`legacy/` holds the $\pi$-descent written for the withdrawn Paper I, the
six-prime certificate pipeline that the v2 rewrite cut, several superseded
one-off scripts, and `gp/m2_katz.gp`, the Katz-side companion to `gp/m2_w1.gp`
that the paper does not quote. None of it supports the paper, it is gitignored, and it is not
published. `legacy/README.md` says what each part was for and, where a script is
wrong, why. Do not cite anything in it. The versions of this directory and of
`../formalisation/` that accompany v2 of the paper, including the resultant
computations that v2 quotes, are at tag `v2` of this repository.
